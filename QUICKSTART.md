## What's Being Monitored

Without any setup, every call tracks:

| Metric | What It Detects |
|--------|-----------------|
| **Jitter** | Robotic/metallic audio (>30ms = warning) |
| **Packet Loss** | Dropouts, gurgling (>10% = warning) |
| **RTT (Latency)** | Overlapping speech (>500ms = warning) |
| **SNR** | Excessive noise (<20 dB = warning) |
| **Clipping** | Audio distortion (>5% = alert) |
| **Dynamic Range** | "PA system" sound (<3 dB = AGC issue) |
| **Response Timing** | Robotic (<100ms) or awkward (>1500ms) gaps |

## Optional: Enable MOS Scoring

MOS (Mean Opinion Score) provides objective quality scores (1.0-5.0).

### Windows (Requires C++ Build Tools)

1. Install [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
2. Select "Desktop development with C++"
3. Run:
   ```bash
   pip install pesq scipy
   ```

### Linux/Docker (Easy)

```bash
pip install pesq scipy
```

### Enable in Config

In [config.py:260](config.py#L260), change:
```python
'enable-mos-scoring': True  # Was False
```

Or in Azure App Configuration:
```json
{
  "enable-mos-scoring": true
}
```

**Note:** MOS scoring is optional. All other monitoring works without it.

## Optional: Azure Log Analytics Setup

For historical analysis and alerting:

### Quick Setup (PowerShell)

```powershell
.\azure-log-analytics-setup.ps1 `
  -ResourceGroup "your-rg" `
  -WorkspaceName "voice-quality-logs" `
  -ContainerAppName "your-app"
```

### Manual Setup

1. **Azure Portal** → "Log Analytics workspaces" → "Create"
2. **Link your Container App:**
   - Portal → Your Container App → "Monitoring" → "Log Analytics"
   - Enable and select workspace
3. **Wait 5-10 minutes** for logs to appear
4. **Run queries** in Workspace → "Logs"

Example query:
```kusto
ContainerAppConsoleLogs_CL
| where Log_s contains "HIGH JITTER"
| where TimeGenerated > ago(24h)
| order by TimeGenerated desc
```

**Sample queries saved in:** `queries.kql` (auto-generated by setup script)

## Real-Time Quality Monitoring

While calls are active, watch for warnings:

```bash
tail -f app.log | grep -E "HIGH JITTER|LOW SNR|INSTANT RESPONSE|CLIPPING"
```

**Example warnings you might see:**
```
HIGH JITTER: 45.2ms avg - EXPECT ROBOTIC/METALLIC AUDIO
INSTANT RESPONSE: 85ms gap (sounds robotic - should be 200-500ms)
LOW SNR: ai audio SNR=18.3 dB (threshold: 20.0 dB)
CLIPPING: ai audio peak=0.983 (distortion risk)
```

These tell you **exactly** what's causing poor quality!

## Troubleshooting

### "I don't see any quality monitoring logs"

**Check:**
1. Files deployed:
   ```bash
   ls -l audio_quality_monitor.py network_diagnostics.py
   ```

2. No import errors:
   ```bash
   python -c "from quality_monitoring import QualityMonitoringSession"
   ```

3. Restart your app after deploying new files

### "PESQ install fails on Windows"

**Solution:** Skip MOS scoring (it's optional)
```python
'enable-mos-scoring': False  # in config.py
```

All other quality monitoring still works!

### "Too many logs"

**Reduce frequency:**
```python
# In config.py
'quality-analysis-interval-seconds': 30  # Was 10
'network-analysis-interval-seconds': 15  # Was 5
```

## Configuration

All settings in [config.py](config.py) lines 227-269:

```python
# Enable/disable monitoring
'enable-audio-quality-monitoring': True
'enable-network-diagnostics': True
'enable-mos-scoring': False  # Requires PESQ
'enable-structured-diagnostics-logging': True

# Thresholds (Azure guide recommended)
'quality-jitter-warning-ms': 30.0
'quality-packet-loss-warning': 0.10
'quality-min-response-gap-ms': 200.0
'quality-max-response-gap-ms': 500.0
```

Override per company in Azure App Configuration:
```json
{
  "enable-audio-quality-monitoring": true,
  "quality-jitter-warning-ms": 25.0
}
```
